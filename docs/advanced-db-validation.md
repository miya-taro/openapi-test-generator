# DDL・期待値ルール・一括照合の検証記録

検証日：2026-10-21。Linux上のブラウザー版とnative pytest runnerを対象に、localhostの模擬API、実PostgreSQL、実InfluxDB 1.xを使用しました。利用者の本番APIやWindowsインストーラーの検証ではありません。

## 実DBとHTTPを使った検証

`docs/run_advanced_db_lab.py`を実行。API側は期待値生成エンジンを使用せず独立した処理を実装しています。各ケース前にシードを復元し、終了時に固有名の検証用テーブル・データベースを削除しました。JSON結果・Excel・JUnitを出力し、HTTP statusとpytestの合否が想定に一致することを照合しました。

| APIの仕様 | 正常系（再実行を含む） | 故障を検出した試験 |
|---|---:|---|
| 入力を10倍してPostgreSQLへ保存 | 2 | 計算違い、別行の更新、保存しない：3件 |
| PostgreSQLで拠点を検索→InfluxDB取得→項目別集計 | 2 | 合計違い、返却欠落、返却重複：3件 |
| 指定されたsite_idをlocation_idより優先 | 2 | 優先順位違い：1件 |
| InfluxDB期間・タグを指定した一括更新 | 2 | 値違い、別対象更新、周囲の更新、一部未更新、余分な追加、更新しない：6件 |
| InfluxDB期間・タグを指定した一括削除 | 2 | 別対象削除、周囲の削除、一部未削除、削除しない：4件 |
| 合計 | **10回すべて合格** | **17回すべて想定どおり不合格** |

fixture内の例外は0件。ログインAPIで取得したauth-keyを使い、HTTP通信はログインを含め54回。テストデータ以外のDB資源は変更していません。

## ブラウザー操作の検証

Chromiumで画面を操作し、DB接続入力→API選択→設定保存→レビュー→実行→Excelダウンロードまで確認しました。

- 新規：期待値ルール、InfluxDB一括更新、一括削除の3ケース。各ケースで正常APIの合格と、故障APIの不合格を確認。
- DDL：テーブル読み込みとカラム候補への反映を確認。SQL実行文を混ぜてもDBへ実行しない。
- 既存回帰：SQLによるレスポンス照合、InfluxDB単一ポイント保存、検証データの準備・復旧の3ケース。
- **6ブラウザーケースが合格**。ダウンロードしたExcelの期待値照合・一括照合シートにも合否が残ることを確認。

## 補助検証

- Python：generator 270件、runner 1,033件、workflow 86件、GUI 104件、計1,493件合格。通常実行では環境依存50件をスキップし、今回必要な実DB／ブラウザー試験は別実行で上記のとおり確認しました。
- JavaScript：171件合格。
- 各Pythonスイートはリポジトリの`verify_all.py`と同様に別プロセスで実行しました。全ディレクトリの一括収集は既存の`runner`モジュール名衝突があるため使用していません。

単体・回帰テストで、DDLの主キー・外部キー・ALTER・既定値・生成列・未対応構文の警告、優先値0/falseの維持、Decimal計算、配列重複比較、将来の処理やレスポンスを正解として参照する定義の拒否、準備失敗時のHTTP未送信、取得上限超過、機密参照の伏字、レビューIDへのルール反映を確認しました。

画面の手順表示では、期待値ルールをまだ入力していなくても送信値入力から次に進めることと、API切り替えで前のルールが残らないことを確認しました。Python/JavaScript lintとGUIのproduction buildも確認しています。

対応範囲と上限は[設定手順](advanced-db-rules.md)を参照してください。この結果は、人が設定したルールそのものの業務上の正しさや、未登録の条件・全APIの網羅を保証するものではありません。
