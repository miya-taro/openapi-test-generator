# 項目間の大小条件と、DBの変更なし確認

## 1. 開始・終了などの大小条件

API契約画面の「項目間の大小条件」で、2項目・比較演算子・小さい試験値・大きい試験値を指定する。
例えば、仕様が `start <= end` なら、`start`、`<=`、`end` を選び、日時の試験値を入力する。
値はJSON形式。数値なら `1`、日時なら `"2026-01-01T00:00:00Z"` のように入力する。
保存時に両方の項目のschemaに適合する値か検証する。

| 設定 | 自動生成する試験 | 期待結果 |
| --- | --- | --- |
| `start <= end` | 小さい値・大きい値 | 定義済みの成功statusとレスポンス契約に適合 |
| 同上 | 同じ値・同じ値 | 同上 |
| 同上 | 大きい値・小さい値 | OpenAPIに定義した4xxと、そのレスポンス契約に適合 |

`<`・`>`・`>=` も選択でき、同値の合否も指定した演算子に従う。両方の項目を送った場合だけ比較する。
片方の省略を禁止する仕様なら、既存の「両方指定または両方省略」も指定する。
日時はタイムゾーンを含めた時刻として比較し、秒の端数も切り捨てない。
通常の項目別試験では対象値を保持し、相方の値で大小条件を満たす。
制約の組み合わせにより生成できない場合は、HTTP送信せず実行エラーとして記録する。

OpenAPIファイルからも同じ機能を使える。JSONリクエストbody直下のschemaに、次の拡張を記述する。

```json
"x-otg-comparison-rules": [
  {
    "fields": ["start", "end"],
    "operator": "<=",
    "lower": "2026-01-01T00:00:00Z",
    "upper": "2026-01-03T00:00:00Z"
  }
]
```

これは本ツールの拡張であり、OpenAPI標準だけで項目間の大小関係が表現できるという意味ではない。
対応するのは、body直下の数値同士、またはdate-time同士。同じ項目を複数の大小条件に使う設定、
ネスト内・クエリ・レスポンスへの大小条件は未対応で、読み込み時に拒否する。業務上の条件を推測して追加しない。

## 2. DBに変更がないことを確認する

DB確認画面で「確認する内容」を「API実行前後でDBに変更がないこと」に切り替える。

1. API操作と対象のPostgreSQLテーブルを指定する。
2. 送信するJSON bodyを入力する。エラーを試す場合は、型違い・必須項目の省略などもそのまま入力できる。
3. 仕様で決まった期待statusを入力する。400・422などをツールが決めることはない。
4. 比較する列をカンマ区切りで指定する。行の識別には主キーを含める。
5. 比較する行の条件をJSONで指定する。`{"site_id": 1}` ならその拠点の行、`{}` ならテーブル全体。
6. 追加・保存し、通常の準備・レビュー・実行へ進む。

GET・POST・PUT・PATCH・DELETEに対応。HTTP直前と応答直後の行を比較し、
追加・削除・指定列の更新を検出する。行順は問わず、同じ値の行が複数ある場合も件数を比較する。
正常な参照APIにもエラー応答にも使用できる。試験対象APIによる変更は検出対象であり、自動で元に戻さない。
同時に他の処理が更新すると区別できないため、分離した試験環境で使用する。

設定例（UIから同じYAMLを保存できる）：

```yaml
scenarios:
  - name: 不正な更新リクエストでDBが変わらない
    request:
      operationId: updateUser
      body:
        id: invalid
    response_check:
      expect:
        status: 422
    db_unchanged:
      - table: users
        columns: [id, name, email]
        where: {site_id: 1}
```

比較範囲はレビュー用マスターとExcelにも含まれる。実行証跡には対象範囲、前後の行と件数、判定を記録する。
認証情報に該当する名前の列は、既存の証跡マスク処理を適用する。

### 範囲と限界

- 指定した範囲・列だけを確認する。指定していない列・他テーブルの副作用を確認済みにはしない。
- 各列の条件は等値のAND。`null` は `IS NULL`。SQLはパラメータ化し、識別子も検証する。
- UIは1テーブル／1範囲。YAMLでは `db_unchanged` に複数範囲を記述できる。
- 最大5,000行。上限を超えた比較は未確認とし、一部だけ比較して合格にしない。実行前に超えていればAPIは呼ばない。
- DB読み取り専用の処理で前後を取得する。APIが確定した変更を確認するため、前後は別トランザクション。
- HTTP応答後に遅れて発生する非同期更新は、この即時比較の対象外。
- 異常系のDB確認は、人が指定したリクエストごとのケース。契約試験の全異常ケースへ自動で付くものではない。
- 大量データの性能試験、JOIN・集計の期待値生成、業務上の正解の推測は、この追加の対象外。
