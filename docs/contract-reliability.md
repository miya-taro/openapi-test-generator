# 合成制約・対応状況・異常系DB比較

## 対応DBの範囲

対応対象は **PostgreSQLとInfluxDB** の2種類です。MySQL／SQL Serverは対象外で、初版の不足機能には数えません。

現時点で両DBの機能は同等ではありません。

| DB | 現在の実装範囲 |
|---|---|
| PostgreSQL | API・DBの対応付け、条件に一致するレスポンスの照合、更新結果・変更なしの確認 |
| InfluxDB | 1.x／InfluxQL。GETの期間内全ポイント照合、固定期間内の変更なし確認、従来の最新1ポイント確認 |

InfluxDBの設定手順・実DB検証結果・残る制限は [InfluxDBの試験](influxdb-testing.md) を参照してください。2.x／3.xは対象外です。

## OpenAPIの合成制約

生成候補を組み立てるための展開済みschemaと、合否判定用の元の契約を分けました。
レスポンスは既存のjsonschemaで、元の `allOf` / `oneOf` / `anyOf` を検証します。

- allOfの同一項目に複数の条件があっても、後の条件を捨てません。
- oneOfは「ちょうど1つ」に適合する場合だけ合格。複数に適合する応答は不合格です。
- 配列要素・入れ子・合成条件の外側にある共通制約も検証します。
- 正常リクエストの代表値も元の契約で検査します。合成できない場合に正常値を捏造しません。
- 合成制約の全分岐・全組み合わせの入力ケース生成を保証するものではありません。対応状況で「一部対応」と表示します。
- 不正なOpenAPIを読み込んだ実行は停止します。エラーを無視して契約検証なしで送信しません。

外部参照、再帰参照、独自format等を含むあらゆるOpenAPIへの完全対応を意味しません。

## 対応状況の一覧

通常のケース準備で、UIのレビュー一覧に「仕様の対応状況」が表示されます。
試験仕様Excel・結果Excelの「対応状況」シート、ケースマスターJSON、HTML結果にも残ります。

| 表示 | 意味 |
|---|---|
| ケース生成済み | 対応する入力ケースがある。全境界の網羅・実行済み・合格を意味しない |
| 未生成 | 生成ルールはあるが、その項目・制約のケースが今回存在しない |
| 一部対応 | 合成制約など、全条件のケース生成を保証していない |
| 未対応 | 専用の入力生成ルール、または検証機能がない |
| 実行時検証 | そのレスポンスを受け取った場合に検証。応答分岐を実際に発生させたという意味ではない |

選択・除外した操作を反映します。この一覧は試験の合否や網羅率ではありません。

## 異常系へのDB変更なし確認の一括設定

1. 契約編集画面でAPI操作を選ぶ。
2. 「自動生成する異常系でDBが変わらないことを確認」を開く。
3. 「比較範囲を追加」でテーブル、比較列、行条件を入力する。複数範囲を設定可能。
4. 補正したOpenAPIを保存し、通常のケース準備・レビュー・承認へ進む。
5. 詳細設定に選択したDBの接続を入力し、逐次実行する。InfluxDBでは開始・終了の固定期間も指定する。

GET / POST / PUT / PATCH / DELETEの各操作で、4xxを期待するケースごとに、実際のHTTP送信の前後で指定したDB行を比較します。400等が正しく返っても、DBが変わっていればNGです。正常系にはこの設定を付けません。
操作ごとの設定は以下の拡張として保存するため、OpenAPIファイルに直接記述しても同じ動作になります。

```json
"x-otg-error-db-unchanged": [
  {"table": "t_data", "columns": ["id", "value"], "where": {"site_id": 1}}
]
```

行条件は等値のANDです。PostgreSQLではnullはIS NULL、空オブジェクトはテーブル全体です。比較列には主キーを含めてください。InfluxDBではnull不可、空オブジェクトは指定期間内の全ポイントです。timeと識別用の全タグを比較列に含めてください。
最大5,000行。事前取得が失敗・上限超過した場合はHTTPを送信せずエラーにします。事後取得が失敗した場合も合格にはしません。
比較する範囲はケースのレビュー情報に含まれ、OpenAPIを変更すれば再承認が必要です。

合否は結果Excel・JUnit・HTMLに反映し、前後の行・件数・判定は `test-result-db-evidence.json` に保存します。UIからも証跡を開けます。機密項目名に該当する値は既存のマスク処理を使います。

同時実行による誤判定を避けるため、設定対象のケースの並列実行は拒否します。他プロセスが同じ行を更新しない検証環境で使用してください。後から起こる非同期更新、未指定の列・テーブルは確認対象外です。DBの自動復旧はしません。

## 確認結果（2026-10-12 日本時間）

- 合成制約の違反、入れ子・配列のoneOf排他性、writeOnly、正常代表値の回帰試験を追加。
- 実HTTP＋PostgreSQLで、5メソッドの自動生成異常系20件：DB変更なしなら全件合格。
- 同じ20件に、更新・挿入・削除の故障をそれぞれ実装：計60件すべて不合格。APIは全件400を返すため、statusだけで誤合格しないことを確認。
- 既存の測定結果GET・CRUD・DB副作用・ブラウザー操作の結合試験も再実行。

今回の追加は優先度の高い上記3点です。ネスト・クエリの項目間比較、JOINの設定UI、トークンの自動更新、非同期DB反映待ちは含みません。
