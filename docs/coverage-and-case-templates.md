# 対応状況と条件別ケース

DB確認設定を選び「実行前の確認内容を作る」を押すと、確認一覧にAPI項目とDB対応、条件別ケースの有無が表示されます。

| 表示 | 意味 |
| --- | --- |
| 照合設定あり | 対応する設定がある。実行済み・合格という意味ではない |
| 未照合 | 解析対象の対応付けが見つからない。DB保存不要の項目かも含めて確認する |
| ケース未設定 | 指定条件のケースが見つからない |
| 要手動確認 | 従来形式・任意SQLの意味・DB列一覧など、自動集計で判断できない |

HTML結果には、対応ケースの合格・不合格・エラー・未確認・スキップ・未実行を別々に表示します。合格ケースが1件あっても、残りを試験済みにはしません。

自動集計するもの：配列INSERTのリクエスト参照、DB取得/SQL結果のレスポンス対応、ルート項目のenum・boolean・省略・配列1件/複数件、2項目のatLeastOne存在条件、変更系APIの異常時DB変更なし設定。

一覧は全組合せの網羅証明ではありません。SQLの業務条件、優先順位、DBに保存不要な項目、未定義の仕様は人が確認します。ネストした条件分岐や合成schemaの全分岐はこの追加集計の対象外です。

## 設定を再利用する

1. API定義を読み込み、DB確認設定ファイルを選ぶ。
2. 「選択したDB確認ファイルを編集用に読み込む」を押す。
3. 各設定の「編集・複製・条件別ケースを作成」を開く。
4. 送信設定、複製先API、期待statusを設定する。条件別ケースは1項目ずつ最大20件。
5. 保存し、改めて実行内容をレビューする。

複製・変更には新しいIDを割り当て、以前の承認を引き継ぎません。DB対応・SQL・固定期待値は引き継ぐため、別APIへ複製した際は見直してください。POSTの日時・主キーが重複する場合、送信設定を変更してから実行します。日時を自動でずらすことはしません。

異常系候補には明示的な期待statusとPostgreSQLのDB変更なし範囲が必要です。事前データ付き・InfluxDBの異常系は、複製後に個別の設定を編集します。期待される業務上の結果は推測しません。

## 検証

- `tests/test_db_coverage.py`: 未照合・省略/null・boolean/数値の区別、未実行やスキップの可視化。
- `gui-tauri/tests/scenario-templates.test.js`: 元設定の保持、IDの分離、明示的な異常系期待値、未対応操作の拒否。
- `gui/tests/test_browser_pwrco.py`: Chromiumから設定の読み込み、複製、条件候補の作成、保存、レビュー、実PostgreSQLを使う39ケース実行、Excel取得。
- `runner/tests/test_pwrco_e2e.py`: 正常/異常38ケースと15種類の故障検出。
- 既存CIはJSON契約、PostgreSQL/InfluxDB 1.x、複数DB参照、ネストINSERT/SQL取得の正常APIと故障APIの試験を継続。

この検証は専用DBと検証用APIに対するものです。利用者の実APIの接続・SQL・仕様設定が正しいことまで保証しません。
