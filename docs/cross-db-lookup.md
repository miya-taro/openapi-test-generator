# 別DBから検索キーを取得して照合する

GETのJSONボディに`location_id`を指定し、PostgreSQLの`t_site`から取得した`site_id`を使ってInfluxDBの計測値を返すAPIを照合できます。参照元・照合先はそれぞれPostgreSQL / InfluxDB 1.xから選べます。

APIには元の`location_id`を送信します。ツール側では人が指定した関係に従って独立に期待値を読み、APIレスポンスの値・件数を比較します。API内部のアクセス順序は検証しません。

## UIの設定例

「DB確認」で対象APIを選び、照合先をInfluxDB、measurementを`measure`とします。PostgreSQL・InfluxDBの接続情報は「詳細設定」で設定します。

「APIの検索条件 → DBの列」の`location_id`行で:

| 項目 | 設定例 |
| --- | --- |
| 送信値 | `"A"` |
| DBの列（照合先） | `site_id` |
| 別DBを参照して比較 | チェック |
| 参照元DB | PostgreSQL |
| 参照DB名 | 空欄なら詳細設定と同じDB。変更する場合はDB名を入力 |
| 参照テーブル | `t_site` |
| 送信値と比較する列 | `location_id` |
| 取得する列 | `site_id` |
| 参照結果の件数 | 1件を要求、または取得した全件を使う |
| 取得値の型 | 取得先がInfluxDBのタグなら「文字列」。整数フィールドなら「整数」など、仕様に従って指定 |
| 参照結果が0件のとき | 未確認として停止 / 空配列の応答を期待 / 指定エラーを期待 |

1件の場合は`=`、全件の場合は`IN`で照合します。全件指定で同じ取得値が複数回出た場合は検索キーを重複排除します。APIの返却行の重複は除去せず、従来通り不一致を検出します。

`start`・`end`は照合先の時刻列へ、`items`は項目列へ直接対応付けます。レスポンスの配列パス`result`と、`time`・`item`・`value`の対応を設定し、保存・準備・レビュー・実行します。

Query/Pathを参照キーにする場合も、別DB参照を選んだ項目の送信値は人が入力します。通常のDBからの検索値自動選択で上書きしません。

## 0件・複数件を推測しない

- **未確認として停止**: 参照結果0件ならAPI実行前に停止します。既定で400や空配列を期待しません。
- **空配列の応答を期待**: 0件時は設定済みの成功statusと、指定した配列パスが空であることを確認します。
- **指定エラーを期待**: 0件時だけ入力した4xxを期待し、実際のエラーレスポンスをOpenAPIに照合します。OpenAPIにもそのstatusの応答定義が必要です。
- **1件を要求**: 2行以上なら、同じIDが重複していても未確認として停止します。先頭行を勝手に選びません。
- **取得した全件を使う**: 複数IDで期待データを検索し、1つのIDしか処理しない不具合も検出します。

参照結果が0件のOR条件と別の有効なOR条件を同時指定した場合は、全体の期待結果を推測せず未確認にします。複数参照で0件時の期待statusが矛盾する場合も停止します。

## 証跡と範囲

`db-scenario-evidence.json`の`db_lookups`に、参照関係・送信値・取得件数・取得値・変換後の検索キーを保存します。`db_response_comparison`には照合先DBの期待データとAPIとの比較結果を保存します。関係の変更は試験定義の変更として扱われ、以前のレビュー承認を流用しません。

- 読み取り専用。自動で参照元や照合先へデータを追加・更新しません。
- 参照元はスカラー値の等価検索1段階です。任意SQL、集計、再帰参照、複合キーJOINのUIではありません。
- 接続はDB種類ごとの既存設定を使います。参照DB名は変更できますが、同じDB種類で別ホスト・別資格情報の接続を追加するUIはありません。
- 参照結果は最大1000行、照合先は既存の最大5000行/ポイント。超過時に切り捨てて合格にはしません。
- 両DBの読み取りをまとめた原子的なスナップショットではありません。テスト中に対象データが変わらない検証環境を使います。
- 検索条件の省略、期間の境界、各IN値の取りこぼしを区別できるデータが照合先になければ、従来と同じく「未確認」です。

## 検証

`runner/tests/test_lookup_response_e2e.py`は、UI生成処理から設定を作り、実PostgreSQL・InfluxDBとHTTP APIを使います。

正常照合、逆方向（InfluxDB→PostgreSQL）、複数ID、0件時の404/空配列/未設定、曖昧な複数件停止を確認します。間違った拠点、条件無視、値の改変、行の欠落・重複、先頭IDのみ取得、0件時の誤statusを不合格にすることも確認します。CIでJSON証跡・Excel・JUnitを保存します。
