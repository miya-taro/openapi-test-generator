# 実HTTP・実DBを使った模擬サービス検証（2026-10-20）

**正常実装に対する122種類のケースと、そのうち21ケースの再実行が合格しました。故障実装に対する30ケースはすべて不合格を検出しました。**
合計173ケース実行です。143種類の独立した試験があるという意味ではありません。
今回はAPIレスポンスを後から改変する方式ではなく、HTTPサービス自身が誤ったDB書き込み・読み取りを実際に行っています。

## 環境と経路

- PostgreSQL **16.15**、InfluxDB **1.8.10**。Dockerコンテナを起動し、実接続して検証。
- 独立実装のPython HTTPサービス。毎回専用のテーブルとInfluxDB databaseを作成し、終了時に削除。
- アプリと同じケースマスター→`runner/pytest_runner.py`→認証・HTTP→DB照合→Excel／JSON／JUnit出力。
- 既存アプリコードの基点は `0ebb97f8a4eec89f11c7757d5f8c432c56d30ff3`。今回追加したサービス・ケース・実行スクリプトのSHA256は集計JSONに記録。
- 既存の計画POST・計画GET・pwrcoは個別のHTTP fixtureを使い、同じ検証スクリプトから順番に実行。

### DB照合の内容

- 全行照合：件数だけでなく各項目の値、欠落、重複を比較。配列の並び順は不問。
- 保存・更新：小数、false、日本語、JSONB内の入れ子、NULLを確認。
- 部分更新：指定したフィールドが変わり、指定していないフィールドと対象外の行が維持されることを確認。
- 削除：対象行が消え、対象外の行が残ることを確認。
- 複数DB：PostgreSQLのlocationからsite_idを引き、InfluxDBの期間・itemsに一致する全ポイントと照合。複数site_id、参照0件も確認。
- InfluxDB：単一ポイントのPOST・PUT・PATCH・DELETE。初期ポイント準備と後片付けも実行。
- API連続実行：作成レスポンスのIDを次の取得へ渡し、取得結果をDBと比較して削除。IDの行が残っていないことを検証スクリプトでも独立に確認。

全件で期待した合否にならなければ検証スクリプトは失敗終了します。

## 開発中に見つけた設定の誤り

初回の検証用定義では、1件のオブジェクト応答を配列として設定し、2ケースが不合格になりました。
UIの「1件」に相当する`array_path: null`へ修正して、DB全フィールド照合が通ることを確認しました。
InfluxDBの新規作成ケースに初期ポイントを指定した定義も、準備段階で拒否されたため修正しました。
これらは今回作った試験定義の誤りです。アプリ本体の判定処理を緩める変更はしていません。
初期実行の証跡は作業環境の`.artifacts/db-lab-first`、`db-lab-second`、`db-lab-third`に保持しています。

## 再現性と証跡

[起動・追加方法](../examples/db-lab/README.md)と[集計JSON](db-lab-validation-results.json)をリポジトリに保存しています。
最終実行の詳細証跡は`.artifacts/db-lab-final/`、回帰試験の実行は`.artifacts/db-lab-regression/`にあります。
これらの詳細ファイルはGit管理外です。

Excelには「結果サマリー」「DBシナリオ結果」「送信リクエスト」「API手順と完了待ち」「DB比較詳細」を出力しています。
DBの期待値・実測値・不一致理由はJSONにも残ります。

CI用の `runner/tests/test_db_lab_e2e.py` も実DBに接続してローカル実行し、**1テスト成功・skipなし**でした。
内部では45ケースの合格と27ケースの故障検出をもう一度確認し、専用テーブル・InfluxDB databaseの削除と、結果JSONへの認証情報の非露出も確認しました。
この72件は上記173件の集計には加えていません。

`--serve`による継続起動も別途試し、ログイン、DBからの3行取得、設定ファイル出力、Ctrl+Cによる後片付けまで確認しました。
CIのDBジョブに回帰試験を追加しましたが、この報告時点で新しいGitHub Actions実行の成功を確認したという意味ではありません。
InfluxDBのPythonクライアントから日時変換の非推奨警告が出ます。今回の検証失敗にはなっていません。

## 保証しない範囲

- UIを人が操作して各設定を入力する工程は今回の検証に含めていません。内部の設定形式と実行経路を検証しています。
- ユーザーの実API・実DBへ接続した結果ではありません。
- 任意のAPIを無設定で試験するものではありません。期待する契約・DB対応は明示的に設定しています。
- 高負荷、同時更新、ネットワーク断による分散トランザクション、トークン期限切れ等は今回の対象外です。
- 故障モードを増やして継続的に検証できる土台であり、あらゆる不具合を網羅した保証ではありません。
