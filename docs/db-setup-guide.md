# UIでAPIとDBの対応を設定する

「1. 対象を登録」でAPI定義・接続先を設定した後、「DB確認」を開きます。新しい対応設定は次の4段階で作成します。

| 手順 | 入力・確認する内容 |
| --- | --- |
| 1. APIを選ぶ | 登録済みAPI、試験名、PostgreSQL / InfluxDB 1.x、確認する内容を選択 |
| 2. 送信値を入力 | APIへ送る値を入力。通常の項目対応ではDB列の入力欄を隠して表示 |
| 3. DBとの関係を設定 | 保存先・検索条件・照合する列・期待ステータスを指定 |
| 4. 試験内容を確認 | 生成される件数、送信内容、期待ステータス、DB設定を確認して「この対応設定を追加」 |

「戻る」や完了済みの手順を押すと、入力を保持したまま修正できます。修正後はプレビューを作り直します。JSONや対応設定が不正な場合は、その手順にエラーを表示します。APIを変更すると、そのAPI用の入力に切り替わります。

追加後に「対応設定を保存」を押します。その後、実行内容の確認・レビュー・承認を行って実行します。設定画面で次へ進むだけでは、対象APIへの送信やDB更新は行いません。

複数行保存・SQLによるレスポンス照合も同じ手順で設定できます。ただし、これらの送信ボディはJSONで入力します。DB列や業務上の期待値は人が指定します。未設定の項目を自動で照合する機能ではありません。

必要な場合は「全項目を一覧で編集」で従来の一括入力に切り替えられます。入力内容は共通です。既存ファイルの読み込み・設定の複製・条件別ケース・共通ルール試験は、引き続き登録済み設定の一覧から使用できます。

## 検証

専用のPostgreSQLとChromiumを用意して、ビルド後に次を実行します。`OTG_INTEGRATION_DB_CONFIG` は専用試験DBへの接続情報をJSONで設定してください。

```bash
npm run build --prefix gui-tauri
OTG_BROWSER_TEST=1 python -m pytest gui/tests/test_browser_db_wizard.py gui/tests/test_browser_post_array.py -q
```

GETの段階別表示・入力保持・保存、POSTの配列保存設定をブラウザで操作し、実際のHTTP通信・PostgreSQL照合・Excel出力まで確認します。正常APIの合格と、値や拠点の選択を故障させたAPIの不合格を確認します。
