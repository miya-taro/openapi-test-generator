# API・DB試験の追加検証（2026-10-21）

localhostの模擬APIと実PostgreSQL・InfluxDB 1.xで検証した。公開サービスや利用者の本番APIにアクセスした結果ではない。API実装と期待値定義は分離し、API側はツールの計算・照合エンジンを使用していない。

## 結果

| 検証対象 | 合格になるべきケース | 故障を検出すべきケース |
|---|---:|---:|
| CRUD・クロスDB・ログイン・認証失敗・DB維持・再実行 | 45/45 合格 | 27/27 検出 |
| 計画登録POST・計画取得GET・電力会社スケジュールPOST | 98/98 合格 | 3/3 検出 |
| 今回追加した境界値・一括保存等 | 17/17 合格 | 28/28 検出 |
| 合計 | **160/160 合格** | **58/58 検出** |

追加の準備失敗4条件も合格。ゼロ除算・存在しないDBカラム・InfluxDBの対象0件・更新前後が同じで変更を判別できない設定は、`UNVERIFIED`になり、HTTPを送らず、PostgreSQL/InfluxDBとも変更されないことを確認した。この4件をAPIの正常実行件数には含めない。

結果の集計は[JSON記録](expanded-db-validation-results.json)にも保存。模擬API内部の想定外例外は0件。終了時に固有名の検証用テーブル・InfluxDBデータベースを削除し、新規の統合試験では削除後の不存在も確認した。

## 今回追加した条件

| 対象 | 正常条件 | 故障条件 |
|---|---|---|
| 入力×10の保存 | 0、負数、正負の丸め。レスポンスは丸め前、DBのnumeric(15,3)は丸め後として別々に照合 | 計算違い、未更新 |
| PostgreSQL参照→InfluxDB集計 | 開始を含まず終了を含む期間、同じ時刻のUTC/JST表記 | 開始時刻を誤って含む、終了時刻を誤って除外 |
| 項目による絞り込み | 1項目のみ、該当項目なし、期間内データなし | 項目条件無視、数値を文字列で返す、0件なのに架空の行を返す |
| 拠点の優先順位 | site_id=0も値として扱う | 0を未指定扱いしlocation_idへフォールバック |
| 複数行の一括保存 | 日本語・引用符、0、負数、false、NULL、入れ子のJSONB、配列 | 行欠落、値違い、NULLを空文字で保存、余分な行、対象外行の変更 |
| 一括保存の失敗 | 後続行が重複なら409で全体ロールバック。不正な後続行・空配列は400で変更なし | 409を返しながら先行行だけコミット |
| InfluxDB一括更新 | 0倍、負数倍、未指定の追加フィールドの保持 | 値違い、対象外ポイントの変更、指定していないフィールドの上書き |

「該当データなしなら空配列」「重複なら409」はこの模擬APIに明示した仕様。他APIの正解としてツールへ固定したものではない。

追加45ケースは保存した定義をnative pytest runnerで実行し、HTTP status・終了コード・JSON判定・JUnit判定を照合。故障ケースは、想定した期待値ルール／DB変更なし確認／InfluxDB変更確認がNGを記録したことも必須とした。別のエラーによる失敗を故障検出成功に数えない。各結果のExcelを読み、サマリーのOK/NGも確認した。

初回には新規の検証定義で400/409のエラーボディ定義が欠けており、正しいAPIを3件NGと判定した。模擬APIが返すJSONに合わせてOpenAPIを修正し、45ケースを再実行した上で上記結果を確定した。これは検証定義の誤りで、ツールの判定を緩める変更はしていない。

## 再実行

専用のDB検証環境を起動する手順は[既存ラボ](db-lab-validation.md)を参照。既存のDBに対し固有名の検証用資源を作成・削除するため、本番DBを指定しない。

```bash
python docs/run_db_lab.py --config examples/db-lab/config.json --output .artifacts/db-regression-new --legacy
python docs/run_expanded_db_lab.py --config examples/db-lab/config.json --output .artifacts/db-expanded-new
```

出力先は未作成のディレクトリを指定する。`runner/tests/test_expanded_db_lab_e2e.py`では同じ45ケース、結果ブック、機密値の非出力、資源削除を検証し、準備失敗4条件も実行する。`OTG_INTEGRATION_DB_CONFIG`と`OTG_INFLUX_INTEGRATION_CONFIG`に専用DB接続のJSONを指定してpytestで実行する。未設定の場合は明示的にスキップされる。

この検証では新たなツール本体の不具合は確認されなかった。任意のAPI・業務仕様の網羅を意味せず、同時実行・性能・障害耐性の検証やWindows実機確認は含まない。InfluxDBクライアントのdatetime非推奨警告は出るが、試験のスキップや失敗は発生していない。
