## 最初の失敗と修正

最初の実行は25成功・3失敗・5接続エラー・16未実施でした。失敗した証跡も保存しています。

* PyPIとnpmの404試験では、以前の試験定義が「本文なし」になっていました。
  実際にはそれぞれ `{"message":"Not Found"}` とJSON文字列 `"Not Found"` が返り、ツールが不一致を検出しました。
  今回の検証用定義を修正し、該当2件を再実行して成功しています。
  **本文の値は今回の実測を固定した互換性確認用の期待値であり、公式仕様として独立に確認した期待値ではありません。**
  404を期待する条件は保持し、単に何でも合格にする変更はしていません。
* crates.ioは当初403でした。ツール名とリポジトリURLを示すUser-Agentを設定して再実行したところ、17件が成功しました。
  サーバー側で最初の403になった理由を確定できたわけではありません。
* 通信制限で拒否された5サービスは、その制限を回避せず未検証としました。

変更したのは公開検証用の試験定義と実行スクリプトです。この検証のためにアプリ本体の合否判定を緩めてはいません。
再試行を含めた送信試行は55件、HTTPレスポンスを受け取った試行は50件です。
47成功は再実行による重複を除いたケース数です。

## 証跡と再実行

[集計結果JSON](public-pytest-validation-results.json)には、各ケースの実測ステータス、判定、curl、
実行日時、初回と再実行の集計、スクリプトと定義のハッシュ、オフライン検証結果を記録しています。

今回の作業環境には、以下の4回の実行結果を保存しました。

* `.artifacts/public-pytest-20261020/` — 初回。失敗・接続エラーを含む
* `.artifacts/public-pytest-identified-20261020/` — crates.ioの17件
* `.artifacts/public-pytest-errors-20261020/` — PyPI・npmの404を再確認
* `.artifacts/public-pytest-more-20261020/` — Go・RubyGems・NuGet

各実行にはOpenAPI定義、ケース定義、実行時のスクリプト、Excel、JSON、JUnit、実行ログを保存しています。
4回分のZIPは `.artifacts/public-api-evidence-20261020.zip` です。
`.artifacts` はGit管理外なので、cloneだけでは今回のZIPや詳細証跡は取得されません。

既存のruntime依存関係をインストールしたPython環境で、リポジトリ直下から実行できます。
出力先には新しいディレクトリを指定してください。

```bash
# 定義の作成だけ。公開APIへのHTTP送信なし
python docs/run_public_pytest_matrix.py --output-dir .artifacts/public-prepared

# 今回接続できた8サービスを、1ケースずつ低頻度で実行
python docs/run_public_pytest_matrix.py --execute \
  --providers jsonplaceholder httpbin pypi npm crates crates-generated goproxy rubygems nuget \
  --output-dir .artifacts/public-executed
```

`--providers` を省略すると13サービスが対象になります。接続できないサービスが残る場合、終了コードは1になります。
`--execute` がない限り実送信しません。通常のCIで自動的に公開APIを呼ぶ設定は追加していません。
403・429・サーバーエラー・通信障害を検出したら、そのホストの後続試験を止めます。
本物の認証情報は使わず、既存の `TEST_AUTH_*` とnetrc認証を引き継がないようにしています。

## 確認できた範囲と限界

今回確認したのは、現在のpytest実行経路での送信、契約照合、判定とExcel・JSON・JUnit出力です。
各公開APIをUIから登録する操作自体の検証ではありません。
OpenAPIは検証対象の項目を抜粋して用意したもので、サービス全体の公式OpenAPIではありません。

JSONPlaceholderの更新系はサービス側が提供する模擬操作です。httpbinの認証もヘッダの有無を確認するもので、
実際のログイン・権限管理を保証するものではありません。公開サービスのDBにはアクセスしておらず、
DB照合、業務ロジック、負荷性能は今回の検証対象に含めていません。

未接続の5サービスについては、必要ドメインのネットワーク許可設定を環境設定の下書きに保存しました。
下書きの保存だけでは通信制限は変わりません。環境設定を確認・保存してPublishし、反映後に残りを再実行する必要があります。
