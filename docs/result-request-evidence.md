# 結果Excelで実際の送信内容を確認する

契約試験・DB試験の結果Excelは、先頭の「結果サマリー」から開きます。合否の件数、期待ステータス、実際のステータス、判定理由を並べ、NG・エラー・未確認など要確認の結果を上に表示します。試験仕様の正常系・異常系の順序は変えません。

「詳細を開く」から契約試験は「実行詳細」、DB試験は「DBシナリオ結果」の該当行へ移動します。「DB比較詳細」では、記録されたDB行・追加行・SQL照合結果の期待値と実際の値を隣に表示します。未確認や未実施は合格に含めません。

各シートは見出しを固定し、絞り込み、折り返し、判定別の色分けを設定しています。長い内容は行の高さに上限があるため、セルを選択して数式バーでも確認してください。契約試験の本文を省略せず残す場合は実行前にfull-bodyを有効にします。

「送信リクエスト」シートで試験ID、判定、HTTPステータス、実際のURL、curl、ヘッダ、ボディを確認できます。DB試験の結果Excelにも同名のシートがあります。

画面ではHTML結果レポートと結果Excelを内部ファイルより先に表示します。HTMLレポートは「要確認のみ」と試験項目・API名の検索で絞り込めます。詳細な値は結果Excelを参照します。保存パスは「保存場所」を開いて確認できます。

curlは、HTTP送信に使用したPreparedRequestの内容から組み立てたBash形式です。JSONの引用符にWindows用のバックスラッシュを重ねずに表示します。Windowsのコマンドプロンプトでは従来のtest_specシートの「実行コマンド」を使ってください。実行自体はPythonのHTTPクライアントを使用しています。

パスワード、トークン、Cookieなどは伏せ字にします。再実行時には必要な認証情報を補ってください。本文のJSONとして必要なエスケープは残ります。バイナリ本文やExcelの文字数制限で省略した本文は表示から再現できないことを明記します。

結果のtest_specシートにある生成時のcurlプレビューは、実際の送信curlに置き換えます。実行していない行は「未実行」と表示し、仮のBASE_URLを実測として残しません。試験仕様だけを出力したExcelは、実行前なので従来どおりプレビューです。


仕様Excelの「送信予定curl（Bash形式）」も実行時と同じリクエスト組み立て処理を使用します。
UIから生成すると設定したBase URLが反映されます。CLIでは `--base-url` を指定してください。
OpenAPIまたはBase URLがない場合は、不完全なcurlを作らず未生成の理由を表示します。
生成時にはAPIへ通信しません。パスワード等は伏字です。ログインで実行時に取得する認証情報は
予定curlに含まれません。実際の送信内容は実行結果Excelで確認してください。
画面で編集した項目はOpenAPIへ保存してから試験ケースを再生成してください。

## 読むための試験仕様

実行前の仕様ExcelはAPIごとの「試験仕様_001」から開きます。表示番号は001からの連番です。
確認すること、対象項目、送信JSON、期待ステータス、応答時間、判定と短縮curlを表示します。
「レスポンス条件」にはステータス別にヘッダ→ボディの順で定義済み条件を表示します。
短縮curlはBash形式で、Content-Lengthなど自動計算する情報を省略しています。
実際の送信ヘッダは実行結果の「送信リクエスト」で確認できます。
従来のtest_specは実行・互換性のため非表示で保持します。内部IDは変更していません。
表示用シートを編集しても試験定義は変わりません。設定はUIから変更し、再生成してください。

## Content-Typeの異常系

JSONまたはmultipartのリクエストに対して、OpenAPIに4xx（個別statusまたは4XX）が
定義されていれば、Content-Typeの不正値と省略の2ケースを生成します。
本文は正常な値を維持し、定義済み4xxで照合します。415だけを要求しません。
4xxの定義がない場合、この2ケースは生成しません。API仕様に沿うstatusを定義してください。
省略ケースのcurlにある `-H 'Content-Type:'` は、空値を送るためではなく、curlの自動付与を
止めてヘッダ自体を送らないための指定です。

## 空文字の正常系

文字列フィールドが型として空文字を許しても、業務処理まで成功するとは限りません。
空文字を正常系の2xxとして自動生成するのは、OpenAPIの当該フィールドに
`example: ""` が明示されている場合だけです。`minLength: 1` などで空文字を
禁止すれば、異常系として4xxケースを生成します。
ログイン失敗のような業務上の期待statusはAPI仕様または手動ケースで指定してください。
