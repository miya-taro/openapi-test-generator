# フェーズ3能力仕様: 共通試験ケースマスター

## CAPABILITY

試験担当者が、OpenAPIから生成したAPI試験とYAMLで定義したDBシナリオを、同じ試験ID・出典・期待結果で追跡できる。アプリは両方の既存形式を言語非依存のケースマスターへまとめ、試験仕様・実行結果・証跡を後続工程で対応付ける。仕様と期待値の承認は人が行う。

## CONSTRAINTS

- 正式な操作面は `gui-tauri/`。新しい成果物生成・確認機能はGUIから使える。
- GitHub、GitHub Actions、外部AI APIを必要とせずローカルで完結する。
- 既存の `test-cases.json`、`test_spec` Excel、`scenarios.yaml` を後方互換で読み込む。既存ランナーを初手で置き換えない。
- Layer 1の既存試験IDを維持する。Layer 2は明示IDがあれば使い、なければ内容が同じ定義から再現できるIDを作る。
- ケースの出典（OpenAPI operationId、シナリオ名・ID、入力ファイル）を保持する。
- レビュー状態は `draft`、`reviewed`、`approved` とし、自動生成時は必ず `draft`。内容変更時は承認を解除する。ユーザーはレビュー前に探索目的で試験を動かせるため、レビュー状態と実行状態は別々に記録する。
- 実行結果は試験IDで結び付け、仕様定義と区別して保存する。秘密の実行時DB・認証設定はマスターへ取り込まない。
- 会社指定の試験書テンプレートは未提供のため、初版は既存 `test_spec` の列と現行DBレポートを基準にする。テンプレート固有の列、承認欄、証跡保持期間は未確定事項として扱う。

## IMPLEMENTATION CONTRACT

### 利用者

- 試験担当者はGUIからケースの一覧・出典・入力・期待値を確認する。
- レビュー担当者はケースを確認済み・承認済みに変更する。
- 実行担当者は承認済みケースを既存のLayer 1 / Layer 2ランナーで実行し、結果を同じ試験IDに記録する。レビュー前の試験は予備実行として明示選択する。

### データモデル

マスターは `api-tester.case-master` 識別子と整数のスキーマバージョンを持つJSONとする。各ケースは一意な `caseId`、種別（`contract` または `db-scenario`）、表示名、出典、実行定義、期待結果、レビュー状態を持つ。実行結果は `caseId` をキーとする独立した実行記録に置き、承認済み仕様を実行のたびに書き換えない。

Layer 1は既存の `id` を `caseId` として保持する。Layer 2はシナリオ定義に任意の明示IDを追加可能にし、未指定時は正規化した定義内容から決定的なIDを作る。重複IDは読み込み時にエラーとし、誤った結果紐付けを防ぐ。

### レビュー・実行状態

レビュー状態は `draft → reviewed → approved` と遷移する。レビュー状態はケース定義の指紋に対応付け、同じ内容のケースを再生成した場合だけ引き継ぐ。レビュー中にOpenAPI、シナリオYAML、ケース定義が変わったら、準備済みマスターと現在の入力の不一致で実行を止め、承認を引き継がない。試験の実行状態・判定はJUnit/Excel/HTMLの実行成果物として別に記録し、実行失敗・警告でレビュー状態を変えない。`draft` のまま実行した予備結果を、承認済みの試験書として表示してはならない。

### 画面・出力

- GUIのLayer 1/Layer 2両画面でケース一覧とレビュー状態を表示する。
- 試験準備時はHTTP送信やDB接続をせず、ケースマスターJSONと汎用Excel試験仕様書を生成する。
- 通常実行は承認済みケースのみ許可し、未承認の試験は専用の予備実行操作でのみ実行可能にする。
- 結果Excel、JUnit XML、HTML結果レポート、失敗ケース再実行は同じケースIDを用いる。
- HTML結果レポートは実行したケースの承認状態を示す。実行していない別Layerの未承認ケースは探索実行判定に含めない。
- 初版Excelは既存列を維持し、テンプレート移植は別途列マッピング可能な境界を設ける。

### 失敗時

- 不正JSON/YAML、未対応スキーマ、operationId不明、重複IDは、元ファイルと項目を示して止める。
- 片方の層の入力が無い場合は存在する層だけのマスターを作り、欠落層を捏造しない。
- 元ファイルが変更された場合、以前の承認を新しい定義へ引き継がない。

## NON-GOALS

- 業務上の正しい期待値を自動で決めること。
- Copilotをアプリから自動起動すること。
- 初版から社内Excelテンプレートを推測して再現すること。
- 既存のHTTP/DB実行エンジンを新規実装すること。
- 実行時のパスワード、トークン、Cookieをケースマスターへ保存すること。

## OPEN QUESTIONS

- 社内Excelテンプレートの必須列、承認欄、シート名、書式。
- APIレスポンスやDBデータを結果報告へどこまで保存し、何日保持するか。
- レビューをケース単位で承認するか、ケースセット全体で承認するか。

これらは内部IDとケース形式の実装を妨げない。初版では既存形式との互換性を優先し、テンプレート・保持方針は設定可能な出力境界に限定する。

## HANDOFF

既存Layer 1 JSONとLayer 2 YAMLを安全に読み取り、重複しないIDと出典を持つ `draft` マスターを生成する。GUIで人がレビューし、承認済み実行または明示的な予備実行へ進める。出力は社内テンプレートが未提供のため汎用試験仕様Excelとし、会社固有の列・書式マッピングはテンプレート受領後に行う。
