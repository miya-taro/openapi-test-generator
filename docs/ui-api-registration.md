# UIからAPIを登録する

1. 「1. 対象を登録」の「APIを新規登録」でAPI名（例 `login`）、パス（`/v1/auth/login`）、メソッド（POST）を入力します。
2. JSONボディの有無と、仕様で定めたレスポンスステータスを指定します。エラーコードは推測せず入力してください。
3. 「登録してボディの項目を設定」を押して下書きを保存します。
4. 表示された項目編集画面でリクエスト・レスポンスに項目を追加し、型・必須・制約を設定して保存します。日時はstringの形式date-timeです。空レスポンスなら「レスポンスボディなし」を選びます。
5. Base URLを設定し、試験ケースを作成・確認します。ログイン結果を後続APIに渡す場合は詳細設定でログイン操作、認証情報、token_path、header_name、header_formatを設定します。

既存のファイルを読み込む必要はありません。別のAPIを同じ定義に追加するときは「選択中のOpenAPIにAPIを追加する」を選び、別名保存します。既存APIの定義は保持されます。

登録直後は項目が空の下書きです。仕様の項目を入力して保存するまで、そのAPIを十分に試験できる定義にはなりません。この入口はJSONボディのAPI用です。クエリやパス変数、エラーレスポンスのボディなどの詳細定義は既存OpenAPIから取り込んでください。

## 正常に受け付けられる値を設定する

リクエストの各項目で「正常系で使う値を指定」をオンにし、有効な値を入力できます。ログインAPIではusernameとpasswordに試験用アカウントを指定します。文字列はそのまま入力し、数値は数値、booleanはtrue/falseを入力します。空文字と未指定はチェックボックスで区別します。

値はOpenAPIのexampleとして平文保存されます。試験専用の認証情報を使い、OpenAPI自体の共有・Git登録には注意してください。パスワード欄は伏せ字表示ですが暗号化保存ではありません。

最小有効リクエストの正常系と、別項目を欠落・型違いにする異常系の基準入力に反映します。空文字など、仕様上の型は正しくても認証できない値を試すケースは別です。その業務上の期待ステータスは明示する必要があります。
