# 操作性の確認（2026-10-21）

API登録から設定保存、実行、結果のダウンロードまでをChromiumで操作し、期待値ルール・DDL・Excelの分かりにくい点を修正した。

## 見つかった問題と修正

| 問題 | 修正・確認 |
|---|---|
| 参照パスをすべて記憶して入力する必要がある | API項目・入力JSONのキー・先行処理の結果を候補表示。値そのものは候補に含めない |
| 計算の参照名を間違えても、直す欄が分かりにくい | 未定義の処理参照・重複処理名・JSON構文誤り等で、該当欄に説明とフォーカスを表示 |
| 文字列の固定値にもJSONの引用符が必要 | 「固定値（文字列）」を追加し、通常のテキストとして入力可能にした |
| 処理の種類を切り替えて戻すと入力が消える | 同じ処理内のDB参照・計算・集計の入力を保持 |
| 処理を途中で削除して追加すると処理名が重複する | 未使用の処理名を割り当てる |
| DDLから無関係のカラムも候補に出る | 選択したテーブルのカラムだけ提示。InfluxDBにPostgreSQLの候補を混ぜない |
| DDL一覧の列や制約が読みにくい | 列見出しと日本語の制約説明を追加 |
| Excelで不一致を探す必要がある | サマリーから不一致の照合行へリンク。HTTP等の失敗は主結果の理由へリンク |
| Excelに使っていない詳細シートが並ぶ | 記録がない詳細シートを出力しない |
| InfluxDBの確認範囲にもNGが付いて原因を誤解しやすい | 範囲・対象・変更前は「参考」、変更後の比較にOK/NGを表示 |

## 検証結果

- JavaScript：16ファイル・175件成功。ESLintとUIビルドも成功。
- Pythonのrunner/gui回帰試験：1,139件成功・47件スキップ。実DB等の追加環境を要求する試験を含み、スキップを成功件数に含めない。
- ブラウザー試験：9件成功。API新規登録、実行・結果ダウンロード・故障検出・再実行、設定復旧2条件、操作性2画面幅、実DBを使う期待値ルール・InfluxDB一括更新・削除を確認。
- PostgreSQL/InfluxDB 1.xを使う3ケースでは、画面から保存した設定を実行。正常な模擬APIを合格とし、保存値の誤りや対象外データの変更を加えたAPIを不合格とすることまで確認。
- 幅1280pxと800pxで、表示中の入力欄・ボタンが画面内に収まることと、入力エラーから修正・プレビュー・戻る操作を確認。スクリーンショットも目視確認。
- Excelは実際に生成したブックを読み、期待値・実測値・失敗箇所へのリンク・不要シート除外を確認。

## 確認の限界と残る操作負担

Linux上のChromiumでの確認であり、Windows版アプリやExcelデスクトップの実機操作、一般利用者を集めた操作性調査は行っていない。画面幅800pxの確認も、スマートフォンでの使いやすさを保証するものではない。

基本のAPI登録から実行までの操作経路は通る。複雑なDB照合には、期待する処理・検索条件・比較対象の理解が必要で、参照パスやJSONを扱う場面は残る。候補表示は設定を助ける機能であり、業務上の正解を推測しない。処理種別を戻した際の入力保持は、ページ再読み込みやAPI切替をまたぐ未保存設定の復元ではない。
